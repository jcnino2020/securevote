# SecureVote visual system

SecureVote is a student voting experience. It should feel welcoming to someone voting on a phone for the first time, while keeping election information trustworthy and easy to scan.

- **Voice:** direct, encouraging, and plain. Show the next action before technical security details.
- **Type:** Bricolage Grotesque gives headings an expressive campus voice; DM Sans keeps forms, dates, and tables clear.
- **Color:** campus blue `#3647b7`, deep indigo `#1c285e`, soft lavender `#e5eaff`, and warm coral `#df704e`. Green, amber, and red retain their status meanings.
- **Public page:** a clear invitation to vote, a ballot illustration, the three real steps, live election information, and privacy guidance.
- **Voter pages:** show what's ready for the student now, then identity details and past receipts. Ballot selections use an unambiguous selected state.
- **Admin pages:** use a compact operations shell with a navy topbar, structured sidebar groups, restrained white evidence panels, and readable tables. The dashboard opens with a dark command view, scoped monitoring context, alert priority, then drill-down sections for signals, controls, identity, ballot activity, the audit stream, and elections.
- **Security language:** distinguish observed audit events, configured controls, and measured service response. A clear alert queue is not a blanket claim that the system is secure. Charts show each event category separately, and unknown turnout is shown as unknown.
- **Accessibility:** keyboard focus, readable contrast, visible statuses, 44px targets, responsive layout, and reduced-motion support.

Election counts, status, receipt data, and security claims are sourced from the application. The ballot illustration is decorative and contains no sample candidate data.
